    01Part 1

    Basic Decision Tree Classifier Construction

    Classification

    Classification

    What common characteristics are shared by one group of people, and not by the other? A test (model) separates them.

    Data model
    • A dataset consists of a number of records.
    • Each record consists of several attribute values.
    • One particular (nominal) attribute is called the label (or class or dependent attribute).
    • Records that share the same label value form a class.
    • We want to discover rules that help predict, given a future (unclassified) record, which class the record belongs.
    Example rules
    • If age < 30 and is not a student ⇒ not a computer owner
    • If age < 30 and is a student ⇒ a computer owner
    • If age is between 30 to 40 ⇒ a computer owner
    • If age > 40 with a good credit rating ⇒ not a computer owner
    • If age > 40 with a bad credit rating ⇒ a computer owner
    Our general approach

    Supervised Learning

    Step 1

    Labeled records

    Prepare a dataset of labeled records.

    Step 2

    Training set

    Draw a random sample (e.g., 80%), call it the training set.

    Step 3

    Train

    Use the training set to train a classifier.

    Step 4

    Test set

    Apply the classifier to the rest (e.g., 20%) of the records (the test set) to evaluate the accuracy of the classifier.

    Training · 80%Testing · 20%
    Supervised

    During the training phase, the machine is fed with labeled records (examples of each class), the learning is supervised. This machine learning approach is called supervised learning.

    Parameter tuning

    For the purpose of parameter tuning, we may divide the data into training-validation-test sets.

    Decision-tree classifier (DT)

    Decision-Tree Classifier

    Internal node

    Each internal node denotes a test on an independent attribute.

    Branch

    Each branch from a node represents an outcome of a test.

    Leaf node

    Each leaf node is associated with a class label.

    We (first) assume that independent attributes are all nominal (or ordinal): they only take on a finite set of named values. Numeric attributes can be mapped to nominal attributes by discretization. Example: income can be grouped into low (< 80K), medium (>=80K, <250K), high (>=250K); a person's height can be very short, short, average, tall, very tall (with a suitable mapping).

    Measuring uncertainty · pick a source

    Entropy

    (Shannon) Entropy is a quantitative measure of uncertainty or randomness. An information source generates symbols; how certain is the recipient in predicting the next one? It depends on the probabilities with which the source generates the symbols.

    H(S)=∑ipilog21pi

    where pi is the probability that the i-th symbol occurs. Larger entropy ⇔ higher uncertainty.

    Entropy of a Dataset

    The concept of entropy is used to select tests in a decision tree. If you are given a new record (the 100,001st) and you are asked to give it a label, how uncertain are you?

    100,000 records · 50,000 'a', 50,000 'b'

    Using entropy, your amount of uncertainty (without any additional information) is 1.0.

    100,000 records · 90,000 'a', 10,000 'b'

    Using entropy, the amount of uncertainty (without any additional information) is only 0.469. In fact, you are somewhat sure that the record should be labeled 'a'.

    Finding a good test · pick a test

    Finding a Good Test

    Start from 50,000 'a' records and 50,000 'b' records (entropy 1.0). A test partitions the records into groups. Weight each group's entropy by its share to get the expected entropy; 1 − expected entropy is the information gain of the test.

    RankTestExpected entropyGain

    A recursive construction algorithm

    Build a Decision Tree: build-tree(D, L)

    D is a training set of data records whose class labels are known. L is a list of nominal independent attributes. Goal: build a decision tree using tests on independent attributes' values.

    Base case

    D is pure

    All records in D are of the same label K: return a tree with only a leaf node labeled K. No test is needed.

    Base case

    L is empty

    No tests can be derived: return a leaf node labeled M, where M = most common label among the records in D.

    Base case

    No meaningful test

    All records in D share the same attribute values for all attributes in L: same action as when L is empty.

    Algorithm build-tree(D, L) {
  If all records in D share the same label 'K'  Return a leaf node with the label 'K';
  If ((L is empty) || (all records in D share the same attribute values)) {
      Let 'K' be the most common label in D;  Return a leaf node with the label 'K'; }
  For each attribute A in L do Compute the expected entropy achieved by using A as the test on D;
  Let A be the attribute which achieves the smallest expected entropy;
  Create a node N with label "A = ?";      // assume A has n possible values a1, …, an
  Partition D into D1, …, Dn, where Di contains all the records with A = ai;
  For each ai do {
      If Di is empty { Let 'K' be the most common label in D; Attach a leaf node to N labeled 'K'; }
      Else Attach the sub-tree obtained by calling build-tree(Di, L-{A}) to N; }
  Return the tree rooted at N;
}

      How to derive a test

      Splitting Nominal, Ordinal and Continuous Attributes

      Nominal · CarType

      Multi-way split: use as many partitions as number of distinct values: Family | Sports | Luxury.

      Binary split: divides values into two subsets: {Sports, Luxury} | {Family}, or {Family, Luxury} | {Sports}, or {Sports, Family} | {Luxury}.

      Ordinal · Size

      Multi-way split: Small | Medium | Large.

      Binary split, order preserving: {Small, Medium} | {Large}, or {Small} | {Medium, Large}. The split point sits on the order large, medium, small.

      Continuous · Taxable Income

      Discretization: transform it to an ordinal attribute, e.g. a multi-way split < 10K, [10K, 25K), [25K, 50K), [50K, 80K), > 80K.

      Binary decision: (A < v) or (A ≥ v), e.g. Taxable Income > 80K? Consider all possible splits and find the best cut: N values give N − 1 possible split points. More computationally expensive.

      Impurity measures · move the slider

      Impurity Measures: Gini, Entropy, Classification Error

      Different decision-tree algorithms use different purity/impurity measures. Example: a node with 6 loan applicants, some who repaid and some who defaulted.

      GINI(S)=1−∑i(pi)2Entropy(S)=∑ipilog2(1/pi)Error(S)=1−maxi(pi)
      MeasureWorkingValue
      Gini · used in CART

      Maximum (1 − 1/nc), where nc is the number of classes. Minimum (0.0) when all records belong to one class.

      Entropy · used in ID3

      Maximum (log2 nc). Minimum (0.0) when all records belong to one class.

      Classification error

      Label all records with the most popular label, and count the mistakes. Maximum (1 − 1/nc); minimum (0.0). E.g. 70% "a", 30% "b": Error = 0.3.

      Gain ratio

      Gain Ratio

      Entropy/information gain has a disadvantage: it tends to prefer splits that result in large numbers of partitions, each being small but pure.

      GainRATIO=GAINSplitINFOSplitINFO=−∑i=1kninlog2nin
      • Parent node's data is split into k partitions; ni is the number of records in partition i; n = total number of records. Gain = reduction in entropy due to the test.
      • Adjust information gain (GAIN) by the entropy of the partitioning (SplitINFO). Higher entropy partitioning (large number of small partitions) is penalized! Used in C4.5. Designed to overcome the disadvantage of information gain.

      When Accuracy Misleads: Imbalanced Classes

      The simple "accuracy" measure may be misleading especially when the classes are "imbalanced".

      Example
      • Two class labels: cancer (+ve) / no cancer (−ve).
      • Only 1% of test records are with cancer.
      • A simple classifier (ZeroR): just say "no cancer". ZeroR ignores every attribute and always predicts the majority class.
      • Classification accuracy 99%.

      Other Metrics: Precision, Recall, F Measure

      Assume two class labels (positive, negative). The positive class is the target class.

      • precision = TP / (TP + FP)
        The fraction of "positive class predictions" that are truly positives.
      • recall = TP / (TP + FN)
        The fraction of "positives" that are predicted positives.
      • F measure = (2 × precision × recall) / (precision + recall)
      • sensitivity (true positive rate) = recall
      • specificity (true negative rate) = TN / (TN + FP)
      • ROC curves: next board.

      Developed in 1950s for signal detection theory to analyze noisy signals. ROC curve plots TPR (a/(a+b); recall) on the y-axis against FPR (c/(c+d); false alarm) on the x-axis. Changing the parameters of the algorithm changes the location of the point.

      Cells: green = correct prediction, red = wrong prediction.

      A classifier with (TPR, FPR): (0, 0) declares everything −ve; (1, 1) declares everything +ve; (1, 0) is ideal. Diagonal line: random guessing. Use the "area under curve" (AUC) to measure overall performance; the ideal model has AUC = 1. Synthetic scores: 50 positive and 150 negative test records.

      04Part 4

      Overfitting and Underfitting

      Training, test, and generalization errors

      Training, Test, and Generalization Errors

      Training error eX

      Given a training set X, we derive a model M. We can apply M on X and measure the error rate of the model in classifying X's records.

      Test error eY

      We can apply the model M on a test set Y.

      Generalization error eG

      Expected error when M is applied to a future, previously-unseen record. (eG is unknown.)

      Since M is derived from X, it naturally fits X. In general, eG > eX. We hope that eG ≈ eY.

      Overfitting

      When we build M, we aim at reducing the impurity of a tree node: we build a model M that reduces eX. M may be fitting the training set too well that it becomes too specific to the training set. Model overfitting ⇒ M is not generally applicable to records other than the training set ⇒ large eG. The more complex the model is, the more likely that the model overfits the training data.

      Income = 60? No → Income = 70? No → Income = 75? No → Income = 85? Yes → …

      A tree that tests one income value at a time reaches eX = 0.

      Overfitting results from decision trees that are more complex than necessary. Training error no longer provides a good estimate of how well the tree will perform on future unseen records.

      Underfitting

      If the model M is too simple, then it probably won't fit even the training set. This is called model underfitting: both training and test errors are large.

      Pre-pruning (early stopping rule)

      Stop the algorithm early before the model becomes a fully-grown tree: stop if the number of instances in a node is less than some user-specified threshold (e.g., 5-10); stop if expanding the current node does not improve impurity measures (e.g., Gini or information gain) by much; limit the tree depth.

      Post-pruning

      Grow the decision tree to its entirety, then trim the nodes in a bottom-up fashion. Estimate a cost complexity R(T) + α|T| (error rate + size); if the cc of the pruned tree T' < cc of T, prune. Class label of a leaf node: majority class of instances in the sub-tree.

      Decision Boundary and Oblique Decision Trees

      Each test in a decision tree derives a decision boundary. Decision boundaries are rectilinear with fixed orientations. In an oblique decision tree, a test condition may involve multiple attributes, such as x + y < 1.

      Leakage and AI Labels

      AI as a subject · evaluation that lies

      Data Leakage in Three Forms

      Leakage: information that would not be available at prediction time gets into training or evaluation. The test accuracy then looks better than the model really is.

      1 · Target leakage

      A feature known only after the outcome

      Example: "cancellation fee charged" when predicting churn (Lab 1's 97.7% model). The model reads the answer.

      Check: for every feature, ask when it is recorded.

      2 · Train/test contamination

      A step that looks at the test set

      Example: selecting features, or fitting a scaler, on all the data before the split. The test set has already shaped the model.

      Check: every fitted step goes after the split, inside each fold.

      3 · Duplicates across splits

      The same record in training and test

      Example: a customer exported twice lands once in each set. The model is tested on what it memorized.

      Check: remove duplicates, or split by customer, before anything else.

      AI as a subject

      Benchmark Contamination

      The problem

      Famous public datasets, and often their answers, are all over the web. A large language model trained on web text may have seen them.

      The risk

      When the model "predicts" the label of a record from such a dataset, it may be recalling it. The score measures memory, not skill.

      What to do

      Test AI methods on fresh or private hold-out data: records collected after the model was trained, or data that was never published.

      The same rule as Part 3: training set and test set should be disjoint. With a pre-trained model you do not control its training set, so you have to choose a test set it cannot have seen.
