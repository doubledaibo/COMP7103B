    01Part 1

    The FP-Growth Algorithm

    An alternative to the Apriori algorithm

    FP-Growth

    An efficient algorithm for mining frequent itemsets, alternative to the Apriori algorithm.

    (a) · I/O efficient

    Compress the database into an FP-tree

    Compress a large database of transactional records into a compact Frequent-Pattern tree (FP-tree) structure. Store the structure in memory to avoid costly database scans.

    (b) · CPU efficient

    Mine the FP-tree

    Run an efficient algorithm to extract frequent itemsets from the FP-tree: a divide-and-conquer recursive strategy. Avoid candidate generation and subset testing.

    Step 1

    Scan DB once, find frequent 1-itemsets (single item patterns).

    Step 2

    Remove infrequent items from transactions.

    Step 3

    Order frequent items in each transaction in descending order of their frequency.

    Step 4

    Scan the (reduced) DB again, construct the FP-tree.

    FP-tree construction · step through

    FP-Tree Construction

    TIDItems bought(Ordered) frequent items

    Let ρs = 0.6 ⇒ min_support = 3 (of 5 transactions). Item frequency: f 4, c 4, a 3, b 3, m 3, p 3.

    Derive a tree path for each transaction. Each node represents a "prefix", given by the path from the root to the node; common prefixes are merged, and the count is the number of transactions with that prefix. Nodes with the same item label form a linked list (dashed). This structure is more compact than the original transactional DB if customers buy similar items (i.e., with long common prefixes).

    Divide and conquer · pick a suffix item

    Mining Frequent Patterns Using the FP-Tree

    Divide the problem into 6 sub-problems, each one discovers frequent patterns that end with a specific item (p, m, b, a, c, f). Start with the last item in order. Follow node pointers from the header table, accumulate the transformed prefix paths of the item into a conditional pattern base, and recursively solve the mining problem for it.

      The conditional FP-tree is repeated on each new tree until it is empty, or it contains only one path. From a single path, each possible item subset derived from it is a frequent pattern.

      FP growth summary

      FP Growth Summary

      Advantages
      • No candidate generation, no subset testing
      • Uses compact data structure
      • Eliminates repeated database scan
      • Basic operation is counting and FP-tree building
      • Usually more efficient than Apriori, especially when there are many long patterns
      Disadvantages
      • Large memory requirement to store the whole tree.
      02Part 2

      Interestingness

      Association rule evaluation

      Pattern Evaluation

      Association rule algorithms tend to produce too many rules. Many of them are uninteresting or redundant.

      Uninteresting or redundant rules
      • {A,B,C} ⇒ {D} vs. {A,B} ⇒ {D}: which rule is better? They are redundant if they have similar support & confidence.
      • {A,B} ⇒ {D} vs. {A,B} ⇒ {D,E}
      Interestingness measures

      Interestingness measures can be used to prune or rank the derived patterns. In the original formulation of association rules, support & confidence are the only measures used.

      Drawback of confidence · drag the counts

      Drawback of Confidence, and Lift

      Association rule: Tea ⇒ Coffee. Its confidence is high, but how good is this rule? Lift is a measure that considers statistical dependency.

      Each column is one group of customers (width = how many). The filled part is the share of that group who buy coffee, P(Coffee | group). The Tea column is the rule's confidence, P(Coffee | Tea); the ¬Tea column shows the coffee rate among everyone else, for comparison. Dashed line: P(Coffee) over all customers.

      Lift=P(Y|X)P(Y)=P(X∧Y)P(X)P(Y)

      Joint probability of X and Y, over the probability of "X and Y" if they are independent. Lift > 1 ⇒ positively associated. Lift < 1 ⇒ negatively associated.

      Too many rules · filter, remove redundant, rank

      Reducing a Rule Set: Filter, Remove Redundant, Rank

      Mining often gives hundreds of rules. Reduce them with exact, checkable steps: keep rules with enough lift, remove redundant rules, and rank what is left.

      A rule is redundant when dropping one item from either side gives a mined rule with similar support and confidence (within the tolerance), as with {A,B,C} ⇒ {D} vs. {A,B} ⇒ {D}. Lift favours rare itemsets, so only rules with enough support are ranked.

      03Part 3

      Mining Quantitative Association Rules

      Quantitative association rules (QAR) · check yourself

      Quantitative Association Rules

      In binary association rule mining, attributes are assumed to be binary (0/1). In practice, many datasets contain quantitative attributes, such as "age" and "income". Quantitative association rules deal with not only binary attributes, but also quantitative attributes.

      Examples

      {age: 40..60, married: Y, income: 500K-1M} ⇒ {properties: 1..1, cars: 1..2}

      {age: 25..30, married: Y, cars: 1..2} ⇒ {children: 1..2, insurance: Y}

      Problem definition · based on Srikant and Agrawal

      Given a dataset D, define the set IR as one that contains 2 kinds of elements: <x: l..u>, where x is a quantitative attribute and l and u define a range of x; and <x: v>, where x is a binary attribute and v is either 1 or 0 (or "yes/no").

      A QAR is an implication rule X ⇒ Y, where X and Y are subsets of IR and no attribute appears in both X and Y.

      Which one of the following is a QAR?

      Example dataset D · set the ranges

      Support and Confidence

      A record r supports X ⊆ IR if r contains values that fall into the corresponding ranges of the attributes mentioned in X. Similar to binary rules, we find all rules X ⇒ Y with sup(X ∪ Y)/N ≥ ρs and sup(X ∪ Y)/sup(X) ≥ ρc.

      QAR is a lot more expensive

      The number of items is much larger. Each (discrete) numerical attribute with a domain of t values derives O(t2) items in IR. Age's domain [0..99] (t = 100) gives Σi=099(100 − i) = 5,050 ranges.

      Mapping QAR to the binary model · change the thresholds

      Mapping QAR to the Binary Model

      Map the dataset with quantitative attributes to one with binary attributes, then apply Apriori. Each quantitative attribute is discretized into n intervals, each deriving a binary attribute by 1-hot encoding: age 28 gives a 1 under <age:25..29>.

          Sequence database

          Sequence Data

          Example: customers (objects) who buy sets of products (itemsets) at different timestamps.

          ObjectTimestampItems
          Formal definition of a sequence
          • A sequence s is an ordered list of transactions s = <t1 t2 t3 …>.
          • Each transaction t is a collection of items t = {i1, i2, …, ik}, associated with a timestamp.
          • Length of a sequence, |s|, is the number of transactions in the sequence.
          • A k-sequence is a sequence that contains k items.
          Definition · type two sequences

          Sequence Containment

          A sequence <a1 a2 … an> is contained in another sequence <b1 b2 … bm> (m ≥ n) if there exist integers i1 < i2 < … < in (indices into the b's sequence) such that

          a1⊆bi1,a2⊆bi2,…,an⊆bin

          Sequential Pattern Mining

          The support of a subsequence w is the fraction of data sequences that contain w. A sequential pattern is a frequent subsequence (support ≥ s). Given a database of sequences and a minimum support threshold s, find all subsequences with support ≥ s. Here ρs = 50%, 5 data sequences.

          Generalized Sequential Pattern (GSP) · try a merge

          GSP and Candidate Generation

          GSP

          Step 1: make the first pass over the sequence database D to yield all 1-item frequent sequences.

          Step 2: repeat until no new frequent sequences are found. During the k-th iteration: candidate generation merges pairs of frequent subsequences found in the (k−1)st pass into candidates with k items; candidate pruning prunes candidate k-sequences that contain infrequent (k−1)-subsequences; support counting makes a new pass over D.

          Candidate generation

          Base case (k = 2): merging two frequent 1-sequences <{i1}> and <{i2}> produces 5 candidate 2-sequences: <{i1} {i2}>, <{i2} {i1}>, <{i1} {i1}>, <{i2} {i2}>, <{i1 i2}>.

          General case (k > 2): merge two frequent (k−1)-sequences w1 and w2 if the subsequence obtained by removing the first item in w1 is the same as the one obtained by removing the last item in w2. The candidate is w1 extended with the last item of w2: if the last two items in w2 belong to the same transaction, it becomes part of the last transaction in w1; otherwise it becomes a separate transaction appended to w1.
