    PageRank and Personalized PageRank

    How to identify "important" nodes? PageRank (PR): a node is important if important nodes link to it. How to measure the "similarity" (or "relatedness") of nodes? Personalized PageRank (PPR): v is related to a start node s if many short paths of links lead from s to v.

    PageRankPR(pi)=1−dN+d×∑pj∈M(pi)PR(pj)L(pj)
    Personalized PageRank from a start paper sPPRs(pi)=(1−d)×{1 if pi=s0 otherwise+d×∑pj∈M(pi)PPRs(pj)L(pj)

    N = total number of papers; d = damping factor (usually around 0.85): the probability of following a citation rather than jumping to a random paper; M(pi) = papers citing pi; L(pj) = number of papers pj cites. A paper's score depends on the scores of the papers citing it, divided by their number of outgoing links; repeat until the scores stabilize (converge). PPR changes only the random jump: the reader always jumps back to the start paper s (here P9). So PPRs(v) = how often a reader who keeps returning to s visits v: high for papers reachable from s by many short citation paths, 0 for papers s cannot reach (P6, P8).

    Community detection · step through

    Communities: Modularity and Label Propagation

    Modularity

    A community has more edges inside it than expected by chance. Modularity Q compares the edges inside communities with what random wiring of the same degrees would give:

    Q=12m∑i,j[Aij−kikj2m]δ(ci,cj)

    Aij = 1 if nodes i and j are linked, else 0; ki = degree of i; m = number of edges; kikj/2m = expected number of edges between i and j under random wiring; δ(ci, cj) = 1 if i and j are in the same community, else 0. Q ranges up to 1; above about 0.3 suggests real community structure.

    Label propagation

    Start with every node in its own community. Repeatedly, each node takes the label that most of its neighbours have. Stop when no label changes.

    Label propagation finds the communities; Q scores them, the way SSE scores a clustering (Lecture 9). Higher Q = better partition.

    Recommender systems · the idea

    What Is a Recommender System?

    A recommender system suggests items a user is likely to want, out of far more items than anyone could look through: films, products, songs, news, people. It learns from past behaviour: what this user, and users like them, have rated, bought or watched.

    Streaming

    “Because you watched …”: the next film or series.

    Online shop

    “Customers who bought this also bought …”.

    Social network

    “People you may know”: personalized PageRank from Part 1 is one way to find them.

    Search

    Query recommendation (Lecture 1): related queries for a vague search.

    Collaborative filtering · this part

    Use other users' behaviour: people who liked what you liked also liked X. User-based, item-based, matrix factorisation.

    Content-based · Part 4

    Use what the items are: genre, description, text embeddings. Works for a new item that nobody has rated yet.

    As a data-mining task: predict the empty cells of the user–item matrix (next board), then recommend each user the top k items they have not seen.

    Recommender systems

    The User–Item Matrix

    Rows are users, columns are items, and each cell is a user's feedback on an item. In real systems most cells are empty, often more than 99%, because each user rates only a tiny share of the items: that is sparsity. Recommending means filling in the empty cells.

    Explicit feedback

    Users say what they think: star ratings, likes. Clear, but rare.

    Implicit feedback

    Behaviour we observe: views, clicks, purchases, watch time. Plentiful, but a missing cell does not mean "dislike".

    Six users rating eight films, 1 to 5 stars (· = not rated). An example made up for this lecture, kept small so you can follow it by hand: only 40% of its cells are empty.

    Item-Based Collaborative Filtering

    Find films rated like this film, then predict from the user's own ratings of them.

    Predictionr^u,i=∑j∈Nk(i;u)sim(i,j)ru,j∑j∈Nk(i;u)|sim(i,j)|

    Nk(i; u) = the k films most similar to i that u rated, with sim > 0.

    Cosine similarity between film columnssim(i,j)=∑uru,iru,j∑uru,i2∑uru,j2

    Sums over all users; a missing rating counts as 0.

    UserFilmk
    Why item-based?

    Item similarities change slowly and can be computed in advance, and there are usually far fewer items than users.

    Personalized PageRank from Part 1 · pick a user

    Recommending with Personalized PageRank

    Turn the ratings into a graph: users on one side, films on the other, and an edge where a user liked a film (rated it 3★ or more; 1★ and 2★ give no edge). With implicit feedback (clicks, views, purchases), each interaction is an edge directly. Then run PPR from the user with the Part 1 formula: the walk goes user → a film they liked → another user who liked it → that user's films, picking one of the L edges at random each step, and keeps jumping back to the start. Recommend the unseen films with the highest PPR.

    Edge: liked (3★ or more) · node size: PPR · orange: the start user · yellow ring: PPR's pick · dashed: other unseen films

    Matrix factorisation · train it

    Matrix Factorisation

    Give every user a vector pu and every film a vector qi of k latent factors, predict a rating as their dot product, and learn the vectors from the known ratings.

    Predictionr^u,i=pu⊤qi=∑f=1kpu,fqi,f

    pu, qi ∈ ℝk: the latent vectors of user u and film i.

    Training objectiveminP,Q∑(u,i)∈𝒦(ru,i−pu⊤qi)2+λ(‖pu‖2+‖qi‖2)

    𝒦 = the known ratings; λ = regularisation weight, which keeps the vectors small.

    Stochastic gradient descent, for each known ratingeu,i=ru,i−pu⊤qi;pu←pu+η(eu,iqi−λpu);qi←qi+η(eu,ipu−λqi)

    eu,i = the error; η = learning rate (0.02 here). The fit is reported as RMSE = √( Σ𝒦 (ru,i − r̂u,i)² / |𝒦| ).

    epochs 0 · RMSE –

    Reading the map: squares are films (qi), the arrow is the chosen user (pu); the two axes are the learned factors, which have no fixed meaning. The further a film lies in the arrow's direction, the higher pu⊤qi; films on one dashed line get the same prediction. Dashed box: not rated by this user. k = 2, SGD in your browser, opening after 300 epochs; RMSE is on the known ratings.

    Evaluating Recommenders

    Offline evaluation · tick the hits

    Precision@k and Recall@k

    Split by time

    Train on everything before a cut-off date; test on what each user did after it. A random split leaks the future into training.

    Score the top k
    Precision@k=|Lk(u)∩T(u)|kRecall@k=|Lk(u)∩T(u)||T(u)|

    Lk(u) = the top k recommended to user u; T(u) = the items u used in the test period; |Lk(u) ∩ T(u)| = the hits. Average over users.

      Beyond accuracy

      Coverage, Popularity Bias and Cold Start

      Bold = one of the 3 most popular films (A, B, C). Compare how many top-3 slots they take under each recommender.

      catalogue coverage
      –

      Coverage

      The share of the catalogue that appears in at least one user's top k:

      Coverage=|⋃uLk(u)||I|

      I = the catalogue; Lk(u) = user u's top k.

      Popularity bias

      Recommending what everyone already watches scores well offline but leaves most of the catalogue unseen.

      Cold start

      A new item or a new user has no ratings, and both kinds of collaborative filtering need ratings. New item: user-based CF finds no neighbour who rated it, and item-based CF has no column to compare, so neither recommends the new Film I. New user: there are no ratings to find neighbours from or to weight. Part 4 shows one fix.

      04Part 4 · AI layer

      Embeddings and LLMs for Recommendation

      AI as a method · new walks

      Graph Embeddings: the node2vec Idea

      Random walks again, as in personalized PageRank. Take random walks on the graph and treat each walk as a sentence, with nodes as words. Then embed the nodes the way word embeddings embed words (Lecture 2): nodes that appear on the same walks end up close together.

      Input · the friendship graph (communities board)
      Output · each node's embedding: 2 numbers = a point

      Colours are the communities found by label propagation; the embedding never sees them, it only sees the walks. Only distances in the right plot matter: its two axes have no fixed meaning. Overlapping circles are nudged apart for display. A stand-in for node2vec's trained model: 120 walks of length 8, co-occurrence within 2 steps, PPMI weighting and a 2-D SVD, computed in your browser.

      AI as a tool · a new film

      Content-Based Recommendation with Text Embeddings

      Red Planet Run is new: nobody has rated it, so collaborative filtering cannot place it. Its description can. A sentence-embedding model turns every film's description into a vector, and cosine similarity finds the films it resembles.

        ej = embedding of film j's description; n = the new film.

        Predicted interestr^u,n=∑j∈Iusim(n,j)ru,j∑j∈Iusim(n,j)

        Iu = films u rated whose similarity to n is above 0.
