    Definitions

    KDD is a Process

    KDD stands for Knowledge Discovery in Databases. It is the process of identifying valid, novel, potentially useful, understandable patterns in data and deriving knowledge from them.

    Data mining

    A step in the whole KDD process in which a specific algorithm is applied to the data for extracting certain specific (interesting) patterns in the data.

    Usually, a user has to decide what kinds of patterns he is interested in and to pick a particular data mining algorithm to extract such patterns.

    One more time

    • KDD: the discovery of knowledge from data (much human involvement)
    • Data mining: the discovery of patterns (mechanical, less human involvement)
    Valid

    Holds on new data, not just the sample.

    Novel

    Not already known or trivially obvious.

    Potentially useful

    Leads to a decision or an action.

    Understandable

    A person can interpret and explain it.

    The KDD process (example) · step through

    A Chain-store Supermarket

    A chain-store supermarket may collect millions of point-of-sale records every day. Each record consists of the items that are purchased together by a customer. What knowledge can we extract from such a database?

    If you were the manager of the supermarket, first ask yourself what kind of knowledge you would like to learn from your data.

    "Hmmm … I am wondering … are there any special groups of items that people usually purchase together in a trip to the supermarket?"

    To achieve the goal, the manager needs the point-of-sale records generated from the different stores be collected into a database.

    The manager sifts through the results obtained from the data mining step and selects those that are actionable, i.e., those that can be translated into knowledge that works to the advantage of the business.

    Iterative

    The result obtained from one run through an iteration of the KDD process may not get what you want. Very often, some steps of the process need to be refined, and then the whole process be repeated.

    Interactive

    Certain amount of human involvement is needed to monitor and to fine tune the steps (such as feature selection and parameter tuning).

    Traditional database systems

    Don't confuse Data Mining with a traditional Database

    Again, KDD is for knowledge discovery; data mining is for interesting patterns discovery (with which knowledge may be derived).

    A traditional DB usually only provides the functions of storing and retrieving facts.

    Prediction and description

    Why simple aggregation is not DM? The knowledge resulting from KDD and data mining should carry certain degree of predictive ability or descriptive (explanatory) ability (or both).

    AI note

    Also not data mining: an AI assistant's fluent summary of a table, with no validated pattern behind it.

    Prediction and description

    Two kinds of Ability

    Prediction

    Prediction involves using the database records that describe information about past behavior to automatically generate a model (or rule) that can predict future behavior.

    Example (predictive ability): the association between milk and bread can be used to predict that there is a high probability that the next customer buying milk would also buy bread.

    Description

    Description involves deriving patterns that summarize the underlying relationships in data and to describe the characteristics of data.

    Example (descriptive ability): a set of documents could be partitioned into clusters such that documents in each cluster are highly similar. From each cluster, we can identify the most frequently occurring words, which can be interpreted as keywords for a given topic.

    DSS and data warehouse

    Decision Support and the Data Warehouse

    DSS

    A decision-support system (DSS) is a system that assists decision makers to make important decisions for an organization or business.

    KDD and data mining are important components in many DSS's.

    Data warehousing
    • A data warehouse is an integration of various departmental databases so that accesses to organization-wide data is possible.
    • A convenient place where KDD and data mining applications are performed.
    • Can also support other DSS tools. For example, On-Line Analytical Processing (OLAP).
    Why a warehouse

    To be effective, a data mining application must have access to organization-wide data. We can integrate departmental databases together into a Data Warehouse.

    Data Mining Tasks

    Data mining tasks: classification, clustering, association analysis, regression analysis

    Classification: Definition

    • Given a collection of records (training set). Each record contains a set of attributes, one of the attributes is the class (or the label, dependent variable).
    • Find a model that describes the class attribute as a function of the values of other attributes (independent variables).
    • Goal: derive a model such that previously unseen records should be assigned a class by the model as accurately as possible. A training set is used to build the model, and a test set is used to evaluate the accuracy of the model.

    Credit card holder data

    Test set

    Gender, Marital Status and Taxable Income are the independent attributes.

    Default Payment is the class attribute (label, dependent variable).

    Training Set → learn a classifier (supervised learning) → Model.

    Test Set → Model. The model predicts "Loan Default" based on a record's independent attribute values.

    Classification: application

    Direct Marketing

    • Goal: Reduce cost of mailing by targeting a set of consumers likely to buy a new cell-phone product.
    • Approach: Use the data for a similar product introduced before.
    • We know which customers decided to buy and which decided otherwise for the previous product. This {buy, don't buy} decision forms the class attribute.
    • Collect various demographic, lifestyle, and company-interaction related information about all such customers: occupation, where they live, how much they earn, gender, age, etc.
    • Use this information as input attributes to learn a classifier model.

    Regression

    Linear Regression and Least squares

    Linear regression

    The goal of (simple) linear regression is to model the relationship between a dependent variable y and an independent variable x using a straight line:

    y=β0+β1x

    To find the best-fitting line, we minimize the cost function (SSE), where (xi, yi) is the i-th data point in the dataset:

    SSE=∑i(yi−(β0+β1xi))2=∑iei2

    Least squares

    With the least squares method, the optimal values of β0 and β1 are:

    β1=∑(xi−x¯)(yi−y¯)∑(xi−x¯)2=Cov(X,Y)Var(X)
    β0=y¯−β1x¯

    x̄, ȳ: means of X, Y.

    Clustering · try it

    Clustering: Definition

    • Given (1) a set of data objects, each having a set of attributes, and (2) a similarity measure among them, find clusters such that objects in the same cluster are more similar to one another, and objects in separate clusters are less similar to one another.
    • Typically, cluster analysis requires a user to define a similarity measure between records. Clustering is then performed based on the principle of maximizing the intra-cluster similarity and minimizing the inter-cluster similarity (distance-based clustering).
    • Unsupervised learning.

    Illustrating clustering

    Intra-cluster distances are minimized. Inter-cluster distances are maximized. Drag a cluster and watch both numbers.

    Clustering

    Clustering: Applications

    Clustering: application

    Document clustering

    Goal: To find groups of documents that are similar to each other based on the important terms they contain.

    Approach: Identify frequently occurring terms in each document. Form a similarity measure based on the frequencies of different terms. Apply a clustering algorithm.

    Applications: Discover topics of interests. Recommend relevant documents (e.g., Google Now news feeds). Query recommendation.

    Query recommendation

    Helps users discover relevant information by suggesting related queries. User queries are often:

    • vague without clear intents
    • too general
    • ambiguous (homonyms and synonyms)
    • poorly formulated (non-expert users often don't know the correct search expression)
    Association rule discovery · try it

    Association Rule Discovery: Definition and Applications

    Given a set of records each of which contains some items from a given collection, discover dependency rules which predict occurrence of some items based on the occurrences of other items.

    Rules discovered

    Or build a rule: click an item once for the left side, twice for the right side, three times to clear.

    Application: marketing and sales promotion

    Let the rule discovered be {Bagels, Mayonnaise} → {Potato Chips}.

    • Potato Chips as consequent ⇒ can be used to determine what should be done to boost its sales.
    • Bagels in the antecedent ⇒ can be used to see which products would be affected if the store discontinues selling bagels.
    Data mining tasks

    Sequence Analysis: Definition and Applications

    A sequence database contains sequences of events. Sequence analysis is about finding interesting, frequently occurring (sub)sequences to predict future behavior.

    Examples
    • Renting movies
    • Buying habits
    • Web surfing behavior
    • Web log analysis
    Web sessions (illustrative)
    • S1: home → search → product → cart → pay
    • S2: search → product → home → cart
    • S3: home → news → home
    • S4: search → search → product → cart → pay

    Frequent subsequence: search → product → cart, found in 3 of 4 sessions. The order of the events matters.

    Calibrating trust

    What today's AI tools do Well, and Badly

    Does well

    • Writing routine pandas and scikit-learn code quickly
    • Explaining an algorithm or an error message
    • Turning free text into structured fields
    • Labelling text with no training data (zero-shot)
    • Summarising long outputs such as rule lists

    Does badly

    • Reporting numbers it never computed
    • Choosing a validation split that leaks the answer
    • Processing millions of records one model call at a time (slow and costly)
    • Explaining reliably why it made a decision
    • Knowing your business context and data quirks

    Audit an AI analyst

    Lab 1 · ungraded practice

    Let an agent explore, then audit it

    An AI agent explores a small customer dataset and reports its findings. The dataset hides three planted problems. Your job is to check the agent's claims, not to redo its work.

    Planted problem 1

    Duplicates

    Some customers appear more than once. Counts and averages are off.

    Planted problem 2

    Impossible values

    Values that cannot be true, such as a negative age or a tenure longer than the company has existed.

    Planted problem 3

    A leaky column

    A column only known after the outcome. It makes any model look excellent.
