    Data Objects and Attributes

    Typical structured data · click the table

    Typical Structured Data

    A collection of data objects and their attributes (values), with a well-defined set of attributes: the schema.

    Attribute

    A property or characteristic of an object. Examples: height/weight of a person; air pressure/wind speed/temperature/lat-long at/of a geographic location. Also known as variable, field, characteristic or feature.

    Object

    A collection of attributes describe an object. Also known as record, entity, tuple.

    Attribute domains

    Each attribute has a domain, which is a set of possible values for that attribute (e.g., integer for "age"; string for "name"). Depending on the domain, attributes are of different types.

    Types of attributes

    Types of Attributes

    Binary

    Values are either 0 or 1, used to denote the presence or absence of a feature.

    Examples: words in a document.

    Nominal

    Values are (discrete) names.

    Examples: a person's name, ID numbers, eye color, zip codes.

    Ordinal

    Values are discrete names that are ordered.

    Examples: rankings/ratings (e.g., taste of potato chips on a scale from 1-10); grades {A, B, C, D, F}; height in {tall, medium, short}.

    Numerical

    Values are numbers representing quantities on which arithmetic operators (e.g., sum, average) can be applied.

    Examples: height in meter, speed in km/h, sale amount in $$$.

    Binary attributes: words in a document. Click a cell to switch a word on or off.

    Document data · type a document

    Bag-of-Words (BoW) Model

    • Each document is modeled as a collection (a set) of terms.
    • Each document is modeled as a vector; each component of the vector corresponds to a term in a given dictionary.
    • The term-frequency model (TF): the value of each component is the number of times the corresponding term occurs in the document.
    Document data · step through

    Stemming & Lemmatization

    Both stemming and lemmatization are techniques to normalize texts, such as converting a word to its "root form" or removing common suffixes. This reduces word variations to facilitate matching.

    Stemming

    Using a set of rules to replace/drop the ending of a word.

    Lemmatization

    Determining the lemma ("root") of a word by looking up a dictionary.

    Word Embedding

    • Learn a vector representation of each word such that words with related/similar meanings are closer in the vector space.
    • Based on the "distributional hypothesis" (words with similar contexts are semantically related).
    • Word2vec, GloVe, BERT, GPT, ELMo.
    • Embedding can be done at the sentence/document levels.

    Set-Valued Data (Transactional Data)

    • Each record (or a "transaction") is a set of items.
    • Example: market-basket data. The set of products purchased by a customer during one shopping trip constitute a transaction, while the individual products that were purchased are the items.
    • Often, data is represented as "inverted lists", in the form item → {a list of transaction ids}. E.g.: bread → {1, 2, 4}; milk → {1, 3, 4, 5}.

    PageRank (PR)

    Graph data

    PageRank

    • An algorithm created by Google to rank web pages based on their importance.
    • It models the likelihood of a random web user visiting a page.
    • Each page pi has a PageRank score, PR(pi).
    • The score is calculated iteratively using the formula:
    PR(pi)=1−dN+d×∑pj∈M(pi)PR(pj)L(pj)
    Where
    • N = total number of pages
    • d = damping factor (usually around 0.85)
    • M(pi) = set of pages linking to pi
    • PR(pj) = PageRank of page pj
    • L(pj) = number of outbound links from page pj

    pj ∈ M(pi), and L(pj) = 3 outbound links.

    PageRank · step through

    How It Works

    • The score of a page depends on the scores of pages linking to it, divided by their number of outgoing links.
    • The damping factor d models the probability that a user continues clicking links versus randomly jumping to a new page.
    • The process repeats until PageRank scores stabilize (converge).

    Similarity and Dissimilarity

    Definitions

    Similarity and Dissimilarity

    Similarity
    • Numerical measure of how alike two data objects are.
    • Is higher when objects are more alike.
    • Often falls in the range [0,1].
    Dissimilarity (distance measure)
    • Numerical measure of how different two data objects are.
    • Lower when objects are more alike.
    • Minimum dissimilarity is often 0.
    • Upper limit varies.
    Proximity

    Refers to how "close" two objects are. It can be expressed by either similarity or dissimilarity.

    Metric

    Some distance measures, such as the Euclidean distance, have the following well-known properties, where d(p, q) is the distance (dissimilarity) between points (data objects), p and q. A distance measure that satisfies these properties is a metric.

    Positivity

    d(p, q) ≥ 0 for all p and q and d(p, q) = 0 only if p = q.

    Symmetry

    d(p, q) = d(q, p) for all p and q.

    Triangle inequality

    d(p, r) ≤ d(p, q) + d(q, r) for all points p, q, and r.

    Similarity between binary vectors

    Simple Matching and Jaccard Coefficients

    When objects p and q have only binary attributes, let

    M01

    the number of attributes where p is 0 and q is 1

    M10

    the number of attributes where p is 1 and q is 0

    M00

    the number of attributes where p is 0 and q is 0

    M11

    the number of attributes where p is 1 and q is 1

    SMC · for symmetric attributes

    SMC = number of matches / number of attributes
    = (M11 + M00) / (M01 + M10 + M11 + M00)

    Jaccard · for asymmetric attributes

    J = number of 1-matches / number of not-both-zero attributes
    = M11 / (M10 + M01 + M11)

    Jaccard distance = (M10 + M01) / (M10 + M01 + M11) = 1 − J

        When TF-IDF Still Wins

        Exact terms, codes, names

        A product code, an error number or a person's name must match exactly. Embeddings treat "KX-9" and "KX-7" as near neighbours.

        Small or specialised corpora

        Jargon, abbreviations and codes that a general embedding model rarely saw in training.

        Cost

        TF-IDF only counts words. Embeddings need a model run for every document and every query.

        Interpretability

        A TF-IDF score is a sum over shared terms you can list. An embedding score has no such breakdown.

        From the search board: query "KX-9", a model that no review mentions

        Caution · discuss

        Embeddings inherit Bias

        Word vectors learn from how people write. For each occupation: is its vector closer to "he" or to "she"?

        How to read it

        Score = cos(word, "he") − cos(word, "she"). Right of zero: closer to "he". Left: closer to "she". GloVe vectors trained on Wikipedia and news text.

        Summary

        Summary

        Objects and attributes

        Data objects are described by attributes; each attribute has a domain. Attributes are binary, nominal, ordinal or numerical. For asymmetric attributes, only non-zero values are important.

        Types of data

        Record, document (BoW, TF-IDF, topic model, word embedding), set-valued, graph (PageRank), ordered and other unstructured data.

        Similarity and dissimilarity

        Single attributes by type; Euclidean and Minkowski distances (L1, L2, L∞); metrics; SMC, Jaccard and cosine.

        From counts to meaning

        Embeddings are dense attributes: the same distance and cosine formulas apply. TF-IDF + cosine stays the baseline to beat.
