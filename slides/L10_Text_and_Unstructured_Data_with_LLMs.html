    01Part 1

    The Text Mining Pipeline

    Recap · Lecture 2, document data

    The Text Mining Pipeline Revisited

    Every text-mining task starts the same way: turn each document into something a computer can compare. Click a stage.

    Bag-of-words · TF

    Each document is a vector; each component counts how many times a term of the dictionary occurs in the document.

    TF-IDF

    Term frequency of t in d, times the inverse document frequency of t: rare terms count more.

    Topic model

    Clusters of words, each a latent topic. A document can cover multiple topics, each with a probability.

    Word embedding

    Words with related meanings are closer in the vector space. Embedding can be done at the sentence or document level.

    02Part 2

    Information Extraction

    Information extraction

    From Documents to a Table

    Information extraction fills a fixed schema from free text: the same fields, types and allowed values for every document. Then the usual data-mining tools apply to the table.

    A job ad · coloured spans are what the rules find
    Rules and regular expressions

    Hand-written patterns such as HK\$\s?[\d,]+. Fast, transparent, exact; brittle when the wording changes.

    Named entities

    A named-entity recognizer tags spans as organization, location, money or date. A first step towards fields such as company, district and salary.

    A fixed schema

    Fields, types and allowed values, decided before extraction. "Not stated" is a valid value and must stay empty.

    Rules · try it

    Rules and Regular Expressions

    One rule per field, run on 12 job ads. Pick a field: the rule's match is highlighted in every ad, next to the right answer (the gold value).

    Evaluation per field

    Precision, Recall and F1 per Field

    Compare each extracted value with the gold set. Score every field on its own: one average hides the field that fails.

    TP: a value was extracted, and it equals the gold value. FP: a value was extracted, but it is wrong or the ad states none. FN: the ad states a value, but the extracted one is missing or wrong.

    P=TPTP+FP   R=TPTP+FN   F1=2PRP+R

    A wrong value counts twice: once as FP (we said something false) and once as FN (we missed the true value).

    Similarity Search at Scale

    The problem · try it

    Exact Nearest Neighbours Cost O(n) per Query

    To find the k most similar items exactly, compare the query with every item: n similarity computations of d numbers each. Time it on this computer with 20,000 embeddings of 384 numbers (random, the size of all-MiniLM-L6-v2's).

    Larger n is extrapolated from the measured time: the cost grows linearly with n.

    Idea 1 · Hashing

    Locality-sensitive hashing: give each item a short signature so that similar items are likely to get matching values. Compare the query only with items whose values match, not with all n. Next: MinHash for word sets, random hyperplanes for embeddings.

    Idea 2 · Graphs

    Link each item to its near neighbours; walk the graph towards the query. The HNSW idea.

    The price

    Both are approximate: much faster, but they can miss a true nearest neighbour. Measure the recall.

    Idea 1 · hashing for word sets · try it

    MinHash for Jaccard Similarity

    Goal: a short signature per document that estimates the Jaccard similarity J of their word sets. A hash function puts all words in a random order; the min-hash of a set is its word that comes first in that order. Two sets get the same min-hash exactly when the first word of A ∪ B is in both sets, which happens with probability |A ∩ B| / |A ∪ B| = J. So with k hash functions, the share of matching min-hashes estimates J.

    Why: comparing two documents then needs only k min-hashes, not their whole word sets. More importantly, documents with matching min-hashes can share a bucket, so a query is compared only with the documents in its buckets instead of all n (locality-sensitive hashing).

    Recap · Jaccard coefficient (Lecture 2)

    J = number of 1-matches / number of not-both-zero attributes = M11 / (M10 + M01 + M11)

    A word set is a binary vector over the vocabulary; 0–0 matches are ignored, so J = |A ∩ B| / |A ∪ B|: shared words over all words in either document.

    Example. A = {storm, warning, schools}, B = {storm, warning, flights, delayed}: |A ∩ B| = 2, |A ∪ B| = 5, so J = 2/5 = 0.4.

    Idea 1 · hashing for embeddings · try it

    Random Hyperplanes for Cosine Similarity

    Goal: the same kind of short signature for embeddings, whose similarity is cosine, not Jaccard. In the picture the vectors are 2-D, so a hyperplane through the origin is just a line.

    Why: 384 numbers per vector become k bits, and vectors with the same bits share a bucket. A query is then compared only with the vectors in its bucket instead of all n.

    1. One bit per line. Draw a random line through the origin. A vector gets bit 1 if it lies on one side of the line and 0 if it lies on the other.
    2. When do u and v get different bits? Only when the line passes between them (the purple lines). A line through the origin can point in any of 180° of directions, and θ of those degrees fall between u and v, so this happens with probability θ / 180°. For example, at θ = 45°, about 1 line in 4 separates them.
    3. Estimate. With k random lines, count the differing bits: θ ≈ 180° × (differing bits / k), and then take cos θ.

    Idea 2 · graph-based search · the idea only · try it

    Graph-Based Search: the HNSW Idea

    Link every item to a few near neighbours. To search, start at an entry point and keep moving to the neighbour closest to the query until none is closer. HNSW adds a sparse top layer with long links for big jumps, then refines on the full layer below. Click to place a query.

    Vector databases

    04Part 4

    Retrieval and RAG

    Keyword retrieval · try it

    BM25 Keyword Scoring

    BM25 refines TF-IDF: extra occurrences of a term within the same chunk help less and less (saturation, set by k1), and long chunks are penalized (length normalization, set by b). The corpus: a made-up library's help pages, 30 chunks.

    score(D,Q)=∑t∈QIDF(t)·f(t,D)·(k1+1)f(t,D)+k1·(1−b+b·|D|/avgdl)

    f(t, D): count of term t in chunk D. |D|: chunk length in terms; avgdl: average length. IDF(t) = ln(1 + (N − nt + 0.5) / (nt + 0.5)), with N chunks and nt chunks containing t.

    Top 5 of 30 chunks, highest BM25 score first · ✓ = a chunk that answers the query · equal scores in chunk order
    One term's weight vs its count f in a chunk (before × IDF)

    What BM25 changes · try it

    BM25 vs TF-IDF on the Same Query

    TF-IDF as in Lecture 2: a chunk's score is the sum over query terms of TF × IDF, with IDF = log10(N / nt). Every repeat adds the full weight again, and length is ignored. BM25 (k1 = 1.2, b = 0.75) caps repeats and discounts long chunks.

    Top 5 of 30 chunks for each score · ✓ = a chunk that answers the query · equal scores in chunk order

    Same query, three retrievers · try it

    BM25 vs Dense vs Hybrid on the Same Query

    Dense retrieval ranks chunks by the cosine of their embeddings (Lecture 2). Hybrid fuses the BM25 and dense rankings (below). ✓ = judged relevant.

    Reciprocal rank fusion (RRF)

    Score = 1 / (60 + BM25 rank) + 1 / (60 + dense rank); rank 1 is best. Only ranks are used, so BM25 scores and cosines need no common scale. 60 is the standard constant (Cormack et al., 2009): it keeps neighbouring ranks close (1/61 = 0.0164 vs 1/65 = 0.0154), so a chunk both rank fairly high (5 and 5: 0.0308) beats one only one ranks first (1 and 30: 0.0275).

    Retrieval-augmented generation · the idea

    What Is RAG?

    An LLM answers from what it learned in training (Lecture 6). It has never seen this library's help pages, so it can only guess, and a guess can sound confident and still be wrong. Retrieval-augmented generation (RAG) adds a search step: first retrieve the chunks that hold the answer, then generate the answer from those chunks only, citing each one.

    LLM alone · illustrative
    Question: how much do I pay if I return a book late?

    “Most libraries charge a small daily fee, often around HK$1 to HK$2 per day. Check with your library.”

    A plausible guess, not this library's rule, and there is no source to check it against.

    RAG · illustrative answer

    “Late books cost HK$1.50 per day each, and the charge for one item stops at HK$130 [C6].”

    Brief · beyond text

    Images and Other Modalities

    Multimodal embedding models (Lecture 2) map images and text into the same vector space. Today's vector methods then work unchanged: cosine search, random hyperplanes, HNSW and dense retrieval. The word-based ones (MinHash on word sets, BM25) need text, so they do not apply to images.

    Search

    Text query, image results

    The text query “damaged parcel” retrieves photos of damaged parcels: dense retrieval, with the query and the photos in one embedding space.

    Scale

    Same indexes

    Image embeddings are vectors too: random hyperplanes, HNSW and vector databases apply as they are.

    Extraction

    Forms, receipts, scans

    A vision-language model (an LLM that also reads images) fills a fixed schema from a scanned form or receipt, as in Part 5. Type and range checks work as before; “appears in the source” needs the text read from the image first (OCR), and that reading can itself be wrong.
