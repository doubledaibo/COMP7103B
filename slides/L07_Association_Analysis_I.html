    01Part 1

    Association Rule Definition

    Market basket analysis

    Market Basket Analysis

    The principal application of association rules is market basket analysis. It models supermarket data and discovers associations between different products (or items) that are bought together by customers.

    E.g.

    {bread} ⇒ {milk}
    {diaper} ⇒ {beer}
    {onion dip, salsa} ⇒ {tortilla chip}

    The left side is the antecedent; the right side is the consequence.

    Data model

    We consider a (market basket) dataset as a collection of transactions (or transactional records).

    Each transaction is represented by a set of items (e.g., {milk, bread, detergent, rice}), also commonly called an itemset.

    Note: for binary association rules mining, the quantity of each item bought is not considered.

    Notation
    • D = dataset
    • I = set of all items
    • N = total number of transactions in D
    • T = a transaction in D
    • a, b, c, … = items
    • X, Y, Z, … = sets of items (itemsets)

    Note: every transaction is an itemset.

    Definition · a toy example · pick items

    Itemsets and Support

    Contains

    Given a non-empty itemset X, a transaction T in D contains X iff X ⊆ T ("T contains X" or "T supports X").

    Support count

    The support count of X, denoted by sup(X), is the number of transactions in D that contain X.

    k-itemset

    If an itemset X contains k items, we call X a k-itemset. {c, d} is a 2-itemset.

    Usefulness and certainty · build a rule

    Association Rules: Support and Confidence

    An association rule is an induction rule of the form X ⇒ Y: if X occurs, then Y is likely to occur. X and Y are non-empty, disjoint itemsets (X ≠ ∅; Y ≠ ∅; X ∩ Y = ∅).

    Support condition · ρs = support threshold
    sup(X∪Y)N≥ρs

    The fraction of transactions that mention all the items in the rule. The mined rules concern items that occur in a good portion of the transactions: they are of sufficient interest.

    Confidence condition · ρc = confidence threshold
    P(Y|X)=sup(X∪Y)sup(X)≥ρc

    The conditional probability that Y occurs in a transaction given that X occurs in the same transaction: the rules are of high confidence.

    How to find rules?

    How to Find Rules?

    Step 1

    Find all the frequent itemsets

    A non-empty itemset S is frequent iff sup(S) ≥ N × ρs. Any valid rule must have all the items mentioned in the rule form a frequent itemset.

    Step 2

    Generate rules from frequent itemsets

    For each frequent itemset S, partition S into two non-empty disjoint subsets X and Y (X ∪ Y = S). If sup(X ∪ Y)/sup(X) ≥ ρc, report X ⇒ Y. Repeat for all possible partitionings of S.

    Example: let ρs = 20%. Step 1 finds all frequent itemsets X s.t. sup(X) ≥ ρs × N = 20% × 25 = 5. From D, the set of all frequent itemsets is:

    Step 1 could be expensive · click an itemset

    Finding Frequent Itemsets and Counting Their Supports

    If there are m different items in a dataset, then there are 2m − 1 possible non-empty itemsets. Checking which itemsets are frequent and finding their supports using a brute-force approach is impractical.

    The lattice

    Given m items, we can arrange the 2m − 1 possible non-empty candidate itemsets as a lattice structure. Level k holds the k-itemsets. A line joins an itemset to one with one more item: the subset relation.

    The Apriori property · pick an infrequent itemset

    The Apriori Property

    Proposed independently by Agrawal and Srikant, and by Mannila, Toivonen and Verkamo.

    Property

    If X is a frequent itemset, then any non-empty subset of X is also frequent.

    Proof. If a transaction T contains X, then for any Y ⊆ X we have Y ⊆ T, so T also contains Y. Therefore sup(Y) ≥ sup(X). Since sup(X) ≥ ρs × N, sup(Y) must be ≥ ρs × N as well. Hence Y is frequent.

    Example: {c, d, e} is frequent in D (sup = 5), and all its non-empty subsets are frequent:

    Conversely

    If an itemset X is not frequent, then any superset of X must not be frequent either. We do not need to check any superset of X and find its support count.

    If we know that {charcoal} is not frequent, then we don't need to check the support of {charcoal, milk}, etc. Apriori uses this to prune the large number (2m − 1) of itemsets to a manageable number.

    Iterative

    The Apriori Algorithm

    Notation

    Ci = set of all candidate i-itemsets · Li = set of all frequent i-itemsets

    1st iteration

    C1 = set of all 1-itemsets (e.g., {{a}, {b}, {c}, {d}, {e}}). Scan the dataset once to find all frequent 1-itemsets (i.e., L1).

    ith iteration

    Construct a candidate set Ci: an itemset X is in Ci if it contains i items and all size-(i−1) subsets of X are in Li−1. Scan the dataset once to find out which itemsets in Ci are frequent; those are put into Li.

    Apriori terminates when a Ci generated is empty. The set of frequent itemsets is the union of all the Li's found in the iterations: C1 → L1 → C2 → L2 → C3 → ⋯ (scan and count; then apriori-gen).

    Algorithm Apriori
Begin
  Scan the dataset D once, and put all frequent 1-itemsets in L1;
  k = 1;
  while (Lk <> NULL) {
      Ck+1 = Apriori-gen(Lk);
      For each transaction T in D do
          For each c in Ck+1 that is a subset of T do
              Increment c's support count;
      Lk+1 = itemsets in Ck+1 whose support count >= ρs * N;
      k++;
  }
End
    Candidate generation and pruning

    From Li−1 to Ci

    The Apriori algorithm uses a function called apriori-gen to generate Ci given Li−1. It considers all pairs of (i−1)-itemsets X and Y from Li−1 that share i−2 common items, and generates the i-itemset Z = X ∪ Y. Each Z is checked to see if all of its size-(i−1) subsets are in Li−1; if yes, Z is put into Ci. We write Ci = Li−1 ⋈ Li−1.

    Example: C3 from L2
    • From {b, d} and {c, d}, apriori-gen generates the 3-itemset {b, c, d}. Since all of {b, c}, {c, d} and {b, d} are in L2, {b, c, d} is included in C3.
    • From {a, b} and {b, c}, apriori-gen generates the 3-itemset {a, b, c}. Since {a, c} is not in L2, {a, b, c} is not included in C3.
    Function Apriori-gen (Lk)
Begin
  Ck+1 = NULL;
  For each itemset X in Lk
    For each itemset Y in Lk
      If (X∩Y contains k-1 items) {       // join
          Let Z = X ∪ Y;
          If every size k subset of Z is in Lk   // prune
              Ck+1 = Ck+1 ∪ {Z};
      }
  Return Ck+1;
End

    Compact Representation

    Compact representation

    Maximal and Closed Itemsets

    The first step of association rule mining is to find all frequent itemsets and their support counts (the set L). L is typically huge! We need a more compact representation.

    Maximal frequent itemset

    An itemset is maximal frequent if (1) it is frequent and (2) none of its immediate supersets is frequent. Maximal itemsets lie on the border between frequent and infrequent itemsets.

    Theorem. An itemset X is frequent iff X is a subset of some maximal frequent itemset, i.e. L = {X | X ⊆ Z, where Z is maximal frequent}. Storing Z (a smaller set) is enough to derive L (a larger set).

    Closed itemset

    An itemset X is closed if none of its immediate supersets has the same support as X.

    Maximal

    Maximal frequent itemsets can infer all frequent itemsets.

    Closed

    Closed frequent itemsets can infer all frequent itemsets and their supports: sup(X) is the largest support among the closed itemsets that contain X.

    We only need to know the maximal frequent itemsets and the closed frequent itemsets and their support counts to find all rules.

    High-Utility Itemsets

    Instead of support, we can evaluate the importance of an itemset by its utility. Each transaction T records the items and their quantities sold: q(a, T) = quantity of a sold in T. Each item a is associated with a unit profit p(a).

    σ(X,T)=∑a∈X(p(a)×q(a,T))π(X,D)=∑T∈Dσ(X,T)

    σ(X, T) is the profit of X in T, counted only if X ⊆ T; π(X, D) is the utility of X in D. Objective: find all itemsets X s.t. π(X, D) ≥ minu, a minimum utility threshold.

    AI as a method · with a classical baseline · pick an item

    Item Embeddings next to Co-occurrence Rules

    An embedding gives each item a vector. Items bought in similar baskets end up close, even if they are never bought together. A rule only sees items in the same basket. Embeddings find substitutes; rules find complements.

    AI as a method · interpretability

    When Interpretable Rules Beat Black-Box Models

    Prefer rules when
    • Promotions: a manager plans a bundle or a discount and needs to see why.
    • Store layout: which products to place near each other.
    • Auditability: each rule points to counts anyone can recompute.
    • Small data: a few thousand baskets are enough for rules, not for a good embedding.
    Prefer embeddings or other black boxes when
    • You rank thousands of items for each customer and only ranking quality matters.
    • Substitutes and "similar items" matter, as in search.
    • Rare and new items need a score that rules cannot give.
    • You can test the result on held-out or live data.
    QuestionCo-occurrence rulesItem embeddings
    What does "related" mean?Bought in the same basket: complementsBought in similar baskets: also substitutes
    Can you check a claim?Yes: count the transactionsOnly indirectly, through a downstream test
    Typical useBundles, shelf layout, cross-sellingRecommendation, search, "similar items"

    Summary

    Summary

    Rules

    X ⇒ Y is valid when sup(X ∪ Y)/N ≥ ρs and sup(X ∪ Y)/sup(X) ≥ ρc. Step 1 finds frequent itemsets; step 2 generates rules.

    Apriori

    Subsets of frequent itemsets are frequent. Apriori-gen joins Lk with itself and prunes candidates with an infrequent subset; one scan per level.

    Compact representation

    Maximal frequent itemsets give all frequent itemsets; closed ones also give their supports. Utility breaks the Apriori property.

    Rules and AI

    Embeddings find substitutes, rules find complements. Recompute every LLM-suggested rule on the data.
